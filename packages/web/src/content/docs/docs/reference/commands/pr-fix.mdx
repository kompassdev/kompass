## Purpose

Use `/pr/fix` when a PR already exists and review feedback or CI failures need another implementation pass.

## Usage

```text
/pr/fix [pr-or-auto-or-context]
```

## Typical flow

- load the PR and existing review state
- check out the PR branch, fetch its base, and merge and push the base when the branch is behind
- implement the requested review or CI fixes on the current branch
- run relevant validation
- in default mode, show the fix summary and wait for user approval before committing or pushing fix changes or replying; required base alignment is applied first
- skip that approval loop only with `/pr/fix auto`
- push the updated branch and reply in the relevant review threads after commit succeeds
