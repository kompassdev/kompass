## Purpose

Use `/ticket/dev` when implementation starts from a tracked ticket and should run through one stateful shipping flow.

## Usage

```text
/ticket/dev <ticket-reference>
```

## Typical flow

- load the ticket and its surrounding context
- implement and validate the ticket
- load uncommitted changes once for branch naming and commit creation
- report `no new commit` when previously committed ticket work can be shipped directly
- push and create the PR from the committed branch comparison

## Common tools

- `ticket_load`
- `ticket_load`
- `changes_load`
- `pr_sync`
